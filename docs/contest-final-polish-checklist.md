# 腾讯游戏大赛最终打磨任务清单

创建日期：2026-07-30

原始适用基线：`v4.30.0`

> 文档状态（2026-08-09 复核）：主体工程阶段已完成，本文件现在是参赛打磨的历史实施台账。带日期的旧版本日志保留当时口径；现行玩法以 `README.md`、游戏内设置说明、`src/config/changelog.ts` 和测试为准。仍然有效的未完成项集中在第 8 节真人走查、投稿材料和最终候选版本发布门禁。

这份清单负责《足球联赛宇宙》参赛前最后一轮可玩性、第一观感和完成度打磨。它只处理已经确认值得做的收口，不继续扩张成足球经理游戏。

相关清单：

- `observer-gameplay-contest-checklist.md`：观察者定位、故事与玩法主循环。
- `ui-polish-checklist.md`：全局视觉、触控、资产和浏览器矩阵。
- `data-chain-optimization-checklist.md`：数据一致性、性能和长期存档。
- `security-audit.md`：生产安全审计边界。

## 0. 执行规则

### 0.1 产品边界

- [x] 玩家仍是足球世界的观察者和历史见证者，不承担阵容、战术、训练、合同和经营职责。
- [x] 判断、主题、档案、声音和分享只改变观察体验，不影响比赛、转会、伤病或 RNG。
- [x] 个人经典宇宙的默认球队名称本轮不改。
- [x] 保留自定义球队入口，不将参赛打磨绑定到单一名称预设。
- [ ] 每个新能力必须优先复用现有权威数据，不维护第二套积分榜、球员统计、故事结论或赛果解释。
- [ ] 不为“增强可玩性”新增货币、体力、每日任务、商城、强制奖励或数值加成。
- [ ] 每个阶段都必须能独立提交、独立回滚、独立验收，不跨阶段堆积未验证改动。

### 0.2 勾选规则

- [ ] 代码写完不代表完成；测试、浏览器体验和性能验证通过后才能勾选。
- [ ] 发现旧清单条目已经实现但未勾选时，先核验证据，再修正清单，不重复开发。
- [ ] 发现实现只覆盖部分语义时，保持未完成，并在进度记录里写明剩余边界。
- [ ] 每阶段完成后更新版本日志、`progress.md` 和本清单，并记录测试数量与关键指标。
- [ ] 默认每阶段单独提交并推送，避免参赛版本出现难以定位的大型混合提交。

### 0.3 当前质量基线（v4.43.0）

- [x] `106` 个测试文件、`801` 项测试通过。
- [x] ESLint、strict TypeScript、PWA 生产构建、冻结安装和 bundle/changelog 预算通过。
- [x] 普通生产包不包含 `window.__gameStore` / `window.__gameAudit`。
- [x] 10 赛季 500 次推进为 0 错误/警告，存档导出导入与继续推进一致。

## 2. P0 赛事周期、赛制与中立场语义

目标：降低洲际杯频率、提高赛事含金量，将世界杯缩短为 3 轮小组赛，并让所有赛事按真实场地语义决定是否存在主客场影响。

状态：核心实现与完整验收已完成；仅保留“改动前后长期冠军/经济分布的独立对照报告”为后续平衡观察，不阻塞本阶段发布。

### 2.1 统一场地政策

- [x] 不再根据 `homeTeamId` / `awayTeamId` 字段本身推断真实主客场；它们在中立场比赛中只用于比分、事件和统计归属。
- [x] 保留单一权威 `isNeutralVenue` 语义，并集中定义各赛事/阶段的场地政策，避免各 handler 手工判断后逐渐分叉。
- [x] “单回合”在本清单中特指单回合杯赛、淘汰赛或附加赛；普通联赛的一场主场赛程不因此变成中立场。
- [x] 中立场必须同时移除模拟、预测、赛前因素和 UI 中的主场优势，不只隐藏“主/客”文案。
- [x] 中立场不得暗中改用固定一方的教练、士气、球员或统计归属；除主场加成外，双方仍使用各自真实状态。
- [x] `MatchFixture`、`MatchResult`、存档导入、历史详情和直播文本保持同一中立场标记。

### 2.2 赛事场地矩阵

- [x] 三级联赛的双循环赛程保留真实主客场与主场加成。
- [x] 超级杯 4 队双循环小组赛保留真实主客场与主场加成。
- [x] 超级杯两回合淘汰阶段每回合保留真实主客场，单回合决赛使用中立场。
- [x] 联赛杯全部单回合淘汰赛使用中立场。
- [x] 洲际杯小组赛、半决赛和决赛全部使用中立场。
- [x] 世界杯小组赛和全部淘汰赛使用中立场。
- [x] 升降级附加赛当前为单回合，改为中立场且不再给高等级球队主场加成。
- [x] 审计所有未来或动态生成的杯赛 fixture；新增赛事必须显式选择 `home/away` 或 `neutral`，不能依赖默认值蒙混通过。

### 2.3 洲际杯周期

- [x] 将洲际杯从 `S2、S6、S10...` 的每 4 季一次，调整为 `S5、S11、S17...` 的每 6 季一次。
- [x] 首届放在 S5，让资格排序至少拥有 4 个完整赛季样本；之后使用现有最近 5 季俱乐部积分。
- [x] `S5 + 6n` 不与 `S4、S8、S12...` 的世界杯年份重叠，避免同季堆叠两项最高级别跨区域赛事。
- [x] 非洲际杯赛季不生成空状态、空赛程窗口、错误新闻或“未参加”记录。
- [x] 自定义球队的地区数量不足时继续安全跳过对应赛事，并按实际活跃赛事计算窗口数量。
- [x] 设置页、赛事说明、新闻、历史、系数排名和更新日志统一显示新周期。

### 2.4 洲际杯参赛与赛制

- [x] 区域内全部球队参赛；最近 5 季俱乐部积分只负责四档分组和同分排序，不再排除低积分球队。
- [x] 大陆杯覆盖全部 16 队：4 组 × 4 队，单循环中立场小组赛 3 轮；每组前 2 名晋级。
- [x] 大陆杯随后进行八强、四强和决赛，全部为单回合中立场，共 6 个赛事窗口。
- [x] 南洲杯与东洲杯各覆盖当地全部 8 队：2 组 × 4 队，3 轮中立场小组赛后进行四强和决赛，共 5 个赛事窗口。
- [x] 三项洲际杯并行使用同一批日历窗口；第 6 个窗口仅大陆杯仍有比赛时，其他杯不得生成空赛果或重复结算。
- [x] 小组排名依次使用积分、净胜球、进球数、赛前俱乐部积分种子和 teamId，避免临时 RNG 决胜。
- [x] 小组赛允许平局；半决赛和决赛平局后进入加时和点球。
- [x] 洲际杯奖项、奖金、俱乐部积分、成就和赛季记录适配小组淘汰、四强、亚军与冠军的新语义。
- [x] 赛程变长后保持“高含金量、低频率”，不增加资格赛、双败、客场进球或复杂抽签规则。

### 2.5 世界杯赛制

- [x] 保留 32 队、8 组 × 4 队和四档抽签。
- [x] 小组赛从主客场双循环 6 轮改为单循环 3 轮，每组每对球队只交手一次。
- [x] 世界杯小组赛所有 fixture 标记为中立场，预测和正式模拟均不得出现主场优势因素。
- [x] 小组前 2 名进入 16 强；排名仍按积分、净胜球、进球数和稳定决胜规则排序。
- [x] 16 强、四分之一决赛、半决赛、决赛全部保持单回合中立场。
- [x] 淘汰赛平局后进入加时和点球，不安排重赛、第二回合或客场进球规则。
- [x] 世界杯阶段总窗口从 10 个缩短为 7 个：3 轮小组赛 + 4 轮淘汰赛。
- [x] 更新赛季结算、奖金、历史结果、赛程标签、关键节点跳转和比赛直播中的轮次语义。

### 2.6 数据迁移与确定性

- [x] 当前不要求兼容旧赛事结构，但导入当前 schema 时必须拒绝同一世界杯小组重复对阵或非法第 4–6 轮。
- [x] 更新赛事状态类型，使洲际杯能够表达小组、积分榜和淘汰赛，且不与超级杯/世界杯状态混用到语义不清。
- [x] 赛事抽签、小组赛程和同分决胜只消费明确、可测试的 RNG；场地标记本身不得额外消耗 RNG。
- [x] 相同种子、球队与历史输入生成相同参赛名单、分组、赛程、赛果和冠军。
- [x] 改赛制后重新校准赛事奖金与俱乐部积分，但不因比赛场次增加而让洲际杯参赛队获得失控的经济优势。
- [x] 新闻、故事、观察主题和关键比赛选择适配小组赛，不把小组第一误写成冠军或淘汰。

### 2.7 验收

- [x] 固定种子测试覆盖洲际杯 S4/S5/S10/S11 周期边界、世界杯 S4/S8 周期和两类赛事不重叠。
- [x] 验证大陆杯每队小组赛 3 场、南洲/东洲杯每队小组赛 3 场，组内不存在重复对阵。

- [x] 赛前解释、判断概率、正式模拟与 MatchResult 对同一 fixture 的中立场语义完全一致。
- [x] 浏览器检查 Cup、Calendar、Dashboard 焦点、Match Detail、直播、History 和 Season Review。
- [x] 运行完整测试、lint、生产构建、bundle 检查、10 赛季审计和 S150 长期审计。
- [ ] 比较改动前后长期冠军分布、参赛队经济和洲际杯积分，确认没有明显集中化或通胀。

## 3. P1 赛季观察档案卡

目标：让玩家在每个赛季结束时得到一个清晰、有记忆点、可回看的观察结论，形成“再看一个赛季”的闭环。

### 3.1 数据语义

- [x] 先审计现有判断记录、主要观察球队轨迹、赛季记录、故事结局、球员统计、奖项与重大比赛，列出可直接复用的数据。
- [x] 卡片只从已冻结的赛季权威记录派生，不重新计算或改写当季积分、球员数据和奖杯。
- [x] 判断统计必须区分“当季”与“生涯”；不能用生涯累计冒充本季表现。
- [x] 若现有历史无法恢复当季判断统计，只保存最小且有上限的赛季观察摘要，不保存重复赛果或文案。
- [x] 同一种子、同一操作序列必须生成相同档案内容；导出图片不得消耗 RNG。

### 3.2 卡片内容

- [x] 第一层只展示：赛季编号、主要观察球队、最终命运和观察印象。
- [x] 最终命运包含联赛排名、升降级、主要杯赛结果，以及与赛季前预期的偏差。
- [x] 观察记录包含当季判断数、命中数、命中率、当前/最佳连中；不足 5 次时继续显示“样本积累中”。
- [x] 选出一场“本季最大命运偏差”，引用统一爆冷定义和真实 MatchResult。
- [x] 选出一名代表球员，读取统一球员统计与奖项身份，不另建评分榜。
- [x] 展示主要观察主题或主要故事的赛季结论，并提供真实证据。
- [x] 最多给出一个“下赛季继续观察”的悬念，不编造尚未发生的剧情。

### 3.3 观察印象规则

- [x] 不使用经理式赛季任务评分，不根据球队成绩奖励或惩罚玩家。
- [x] 0 次判断显示“纯粹见证者”，不作能力评价。
- [x] 1–4 次判断显示“记录形成中”，不展示误导性的高低评级。
- [x] 5 次及以上才根据命中率和样本量给出克制的观察印象，阈值必须可测试且文案不羞辱玩家。
- [x] 评级只用于本季档案与视觉纪念，不解锁数据、球队能力、操作权限或隐藏信息。
- [x] 不增加可刷取的观察经验、等级、货币和重复奖励动画。

### 3.4 页面与交互

- [x] 赛季结束后的首个稳定页面能够看到档案卡入口，但不阻挡继续进入新赛季。
- [x] `Season Review` 展示完整卡片，`History` 赛季目录展示紧凑摘要和入口。
- [x] 卡片中的球队、球员、比赛和奖杯仅在历史数据仍可解析时提供有效跳转。
- [x] 移动端先展示结论，再展示证据；不得出现嵌套卡片或长篇说明。
- [x] 提供“保存档案图”时，真实文本保持清晰，中文、长球队名和 DPR 缩放不得裁切。
- [x] 浏览器不支持导出或分享时，完整档案仍可在游戏内回看。

### 3.5 存储与性能

- [x] 历史档案复用现有赛季数量上限；不得为每场比赛复制完整事件。
- [x] 明确新增字段的 schema、上限、导入校验和存档体积影响。
- [x] 卡片渲染和图片导出按需加载，不增加 Dashboard 初始依赖图。
- [x] S150 存档继续低于现有 4 MB 预算。

### 3.6 验收

- [x] 固定种子覆盖：纯观察、小样本、足够样本、主题开启/关闭、升降级、夺冠、无奖杯和重名球员。
- [x] 刷新、导出、切换主要关注球队和进入下一赛季后，旧档案保持不变。
- [x] 在 `320x568`、`390x844`、`430x932`、`1440x900` 检查卡片与导出结果。
- [x] 运行完整测试、生产构建、bundle 检查、10 赛季审计和按风险决定的 S150 审计。

- [x] 覆盖 Transfers、Market、History、Season Review、Chronicle、Legends、Advanced Search、Settings。

- [x] 为每个页面记录主操作、返回路径、横向滚动、最小点击区域、最小正文和最长文本表现。

## 8. P0 盲测、评审路线与投稿收口

目标：用真实陌生玩家验证前五分钟，而不是只证明自动化脚本能通过。

### 8.1 五分钟盲测

- [ ] 至少邀请 3 名未接触项目的人独立体验，不口头解释。
- [ ] 记录他们是否在 30 秒内理解“观察而非操控”。
- [ ] 记录他们是否在 60 秒内进入宇宙并知道主要操作。
- [ ] 记录他们是否能完成一次判断、推进和结果理解。
- [ ] 记录他们能否复述一条球队故事和一个赛果原因。
- [ ] 记录所有超过 10 秒的停顿、误点、返回失败和看不清文字的位置。
- [ ] 只修复至少两人重复遇到的问题；单个审美偏好不继续扩展系统。

### 8.2 十五分钟评审路线

- [ ] 复核现有推荐种子和内部 15 分钟浏览器路线仍与当前版本一致。
- [ ] 固化路线节点：开始观察、焦点判断、比赛揭晓、爆冷解释、故事升级、赛季/历史悬念。
- [ ] 路线使用真实模拟和公开种子，不写死演示赛果。
- [ ] 准备路线失败时的备用种子或恢复步骤，不在评审现场依赖开发工具。
- [ ] 录制一次不剪辑的内部完整走查，确认 15 分钟内没有死路和等待空档。

### 8.3 投稿材料

- [ ] 前 30 秒视频直接展示“判断 -> 比赛 -> 结果解释 -> 故事变化”。
- [ ] 准备桌面、移动端、比赛直播、赛季档案和长期历史截图。
- [ ] 文案明确差异化定位：“无操控、无战术，观察命运如何形成历史”。
- [ ] 说明固定种子复现、纯前端离线、长期存档和自动演化的技术亮点。
- [ ] 投稿前联网核对当届比赛规则、交付格式、演示地址、素材权利和名称要求。
- [ ] 个人经典宇宙名称保持不变；只有投稿规则确实要求时，再单独处理原创参赛预设。

### 8.4 发布门禁

- [ ] 使用规定 Node/pnpm 版本执行冻结安装。
- [ ] 运行 `pnpm test`、`pnpm lint`、`pnpm build`、`pnpm audit --prod`。
- [ ] 运行前五分钟、比赛直播、移动推进、离线恢复和 Error Boundary 浏览器流程。
- [ ] 运行 10 赛季数据审计；最终候选版本运行 S150 审计。

- [ ] Vercel 生产地址完成桌面、移动端、冷启动、PWA 更新和回退检查。
- [ ] 冻结候选版本后只接受 P0 缺陷修复，不再追加玩法系统。
