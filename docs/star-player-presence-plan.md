# 球星存在感与追踪系统实施方案

创建日期：2026-08-12

> 历史台账：第一版已随 v4.53.0 实现并通过发布级验证。未勾选的原始方案不代表现行待办；当前状态以 [`current-status.md`](current-status.md) 为准。与 `coach-tactics-formation-plan.md` 共用比赛上下文、首发快照、解释层和直播接入。

这份方案只增强球星在足球宇宙中的长期存在感，不增加球员养成、手动训练、签约经营、卡牌收集或复杂临场指挥。玩家仍然是观察历史的“上帝”，只是能够更容易发现、追踪并理解那些真正改变比赛和时代的球员。

**完成规则：只有球星长期供给、比赛权威影响、统一评价、直播表现、追踪体验、移动端展示和长跑验证全部通过，相关任务才可以勾选。**

## 1. 已确认的产品结论

- [x] 第一版采用“轻量球星观察”方案，不建立永久 `isStar` 身份或星级养成系统。
- [x] 基础能力 `rating`、赛季表现 `seasonScore`、近期影响和关注状态保持为不同概念。
- [x] 球星不获得独立万能光环；其胜负影响来自阵容能力、位置职责和权威事件链路。
- [x] 球员中心增加“球星观察”，包含世界焦点、新星雷达和我的关注。
- [x] 世界焦点采用资格制，符合球星标准的现役球员都可展示，不设固定人数上限。
- [x] 每场直播最多展示 5 名焦点球员，不要求主客数量对等；资格不足时允许少于 5 人或无人入选。
- [x] 门将、后卫、中场和前锋拥有同等成为焦点、当选最佳球员和进入专栏的机会。
- [x] 新星定义为赛季开始时未满 23 岁，只展示年龄、当前能力、真实比赛表现和近况，不泄露隐藏潜力。
- [x] 我的关注最多保存 8 名球员。
- [x] 教练决定球队如何比赛，球星体现谁最可能执行并改变关键局面；两套系统共享一条数据链路。
- [x] 不修改球队名称、自定义球队能力或观察者游戏模式。

## 2. 当前基线与已确认问题

### 2.1 已有能力

- 阵容中不同位置的高能力球员已经进入球队攻、中、守加成，伤停会削弱实际出战强度。
- 进球者选择已经使用位置、`goalScoring` 和关键战 `clutch` 权重。
- 门将关键扑救、后卫门线封堵、普通扑救、拦截和解围已有事件或统计来源。
- `MatchResult` 已保存事件、实际出场快照、防守贡献和 UUID 口径的 MOTM。
- 当前赛季综合评分已经使用位置表现、分钟可信度、出勤和赛事强度，四位置可以在同一 0-100 尺度比较。
- Canvas 能把权威事件球员 UUID 映射到场上位置，也已有单个球员高亮和姓名显示能力。

### 2.2 需要解决的问题

- 球员对球队的影响大多折叠为匿名“阵容加成”，玩家很难知道具体是谁带来了差异。
- 助攻者和定位球执行者对个人能力考虑不足；防守统计归属的能力差异也偏弱。
- MOTM 没有完整计算关键扑救、门线封堵、拦截和解围，天然偏向进球与助攻球员。
- 关键扑救/封堵 deny 链目前在淘汰赛关闭，越重要的比赛越难产生门将和后卫的决定性高光。
- 初始生成器明确制造的星级偏置只覆盖中场和前锋，防守位置缺少对等的明星长尾。
- 青训换代的能力上限实质过低，导致长期世界出现严重球星断代。
- “最佳新星”当前按弱队头号射手近似，并不是真正的年轻球员奖项。
- 球员详情近况主要强调进球，助攻、扑救和防守高光难以形成连续故事。
- 当前没有关注球员能力，玩家无法跨转会持续追踪自己感兴趣的人。
- 九种榜单平铺在同一级页签，移动端查找成本高，原始总数榜缺少每 90 分钟和出场样本语境。

### 2.3 审计证据

- 30 个种子 × 20 个赛季的综合评分审计通过：四位置中位数最大差 1.9，P90 最大差 2.0，无 NaN、Infinity、负分或超过 100 分。
- 一个真实世界长跑中，能力 85+ 球员从第 1 季的 63 人降至第 10 季的 16 人，第 20、30、40 季均为 0 人。
- 同一长跑中，第 20 季全世界最高能力只有 77，第 40 季最高能力只有 79。
- 16,000 名青训替代球员抽样中，潜力中位数约 54、P95 约 70、最高仅 77；四个位置都没有形成精英长尾。

因此第一优先级不是增加球星 UI，而是先恢复长期可持续的稀缺球星供给。

## 3. 核心概念与系统边界

### 3.1 四个概念必须分开

| 概念 | 含义 | 是否公开 | 是否直接改变比赛 |
|---|---|---|---|
| 基础能力 `rating` | 球员当前实力 | 是 | 是，继续进入阵容和事件链路 |
| 赛季表现 `seasonScore` | 本赛季真实产出、出勤和赛事强度 | 是 | 否，避免表现反向制造下一场结果 |
| 近期影响 | 最近最多 5 次实际出场的事实摘要 | 是 | 否，只用于观察与焦点选择的小权重 |
| 焦点身份 | 当前是否值得被专栏或某场直播重点观察 | 是 | 否，本身不是额外 buff |

- 隐藏 `peakRating` 继续只用于发展系统，不能出现在专栏、筛选文案或直播中。
- “世界焦点”和“新星雷达”每次由当前世界事实派生，不写入永久球星标签。
- 历史荣誉只能作为同档候选人的小幅排序因素，不能让退化球员永久占据当季焦点。
- 关注状态只代表玩家兴趣，不影响模拟、新闻概率、转会或奖项。

### 3.2 第一版明确不做

- 不增加球员训练、技能树、化学反应、球星卡和抽取机制。
- 不允许玩家指定核心战术、点名传球或手动盯防。
- 不建立完整的一对一对抗数值模拟或新的细分球员属性体系。
- 不为球星额外叠加固定攻防百分比、士气光环或队友加成。
- 不让每场比赛强制出现焦点球员，不给普通球员滥发“球星”标记。
- 不建立另一个公开的“球星分”，避免与 `rating` 和 `seasonScore` 形成第三套榜单歧义。
- 不保存可由近期比赛结果重新派生的大量近况文本。

## 4. 长期球星生态

### 4.1 目标分布

以约 700 名现役球员为基准，完成换代后的长期世界建议稳定在：

- 能力 85+：约 25-45 人。
- 能力 90+：约 6-15 人。
- U23 且能力 80+：约 3-10 人。
- 四个位置都应周期性出现能力 85+ 球员，不能长期由中前场垄断。
- 全体能力中位数和 P90 不应持续膨胀；修复稀缺长尾不能变成全员巨星。

这些是多种子长期统计区间，不是每一个赛季必须精确达成的硬配额。

### 4.2 生成原则

- [ ] 将青训生成改为“普通主体 + 优秀苗子 + 极少精英潜力”的混合分布。
- [ ] 精英尾部保持稀少，建议初始概率约 1%-2%，最终以长跑结果校准。
- [ ] 俱乐部声望、地区足球水平和青训背景只调整概率，任何球队都保留极低概率诞生顶级球员。
- [ ] 四个位置使用同一潜力等级概率，再根据位置生成适合的能力与技术标签。
- [ ] 年轻球员初始能力需与年龄和潜力一致，确保少量新星能在 19-22 岁真正进入比赛，而不是只在退役前达到峰值。
- [ ] 初始世界生成的明星偏置扩展到 GK/DF，同时避免改变既有球员名字或球队配置。
- [ ] 发展、伤病、衰退和退役仍可让天才失败；高潜力不保证成为球星。
- [ ] 使用独立确定性随机流生成球员层级，避免无关 UI 或比赛事件改变青训结果。

## 5. 世界焦点与新星雷达

### 5.1 世界焦点

球员中心默认区域增加“世界焦点”：

- 采用资格制，不设固定展示人数上限；达到统一门槛的现役球员全部进入。
- 页面按内部优先级排序，并通过位置筛选和渐进加载控制信息密度，不以截断人数隐藏合格球员。
- 候选人必须为现役球员，并达到动态能力门槛；赛季早期可以更多依赖基础能力，赛季深入后逐步纳入可信的赛季表现。
- 内部排序可以组合基础能力、已收缩的赛季综合分、最近 5 次出场影响和少量当季荣誉权重。
- 内部排序只负责选人，不在 UI 显示一个新的神秘数值。

建议初始内部权重：

```text
世界焦点优先级
= 50% 当前基础能力
+ 30% 赛季综合评分
+ 15% 近期比赛影响
+ 5% 当季重要荣誉或关键战事实
```

### 5.2 新星雷达

- 年龄门槛建议为赛季开始时不满 23 岁。
- 所有达到资格线的 U23 球员都可展示，不设固定人数上限；页面通过紧凑列表控制信息密度。
- 排序以当前能力、可信赛季表现和近期实际出场为主，不使用隐藏潜力。
- 允许低级别联赛新星进入，但页面明确标注赛事级别、分钟和可信度。
- “快速成长”只能根据过去已冻结赛季的 rating 变化得出，不能从未来潜力推测。

建议初始内部权重：

```text
新星关注优先级
= 55% 当前基础能力
+ 35% 赛季综合评分
+ 10% 近期比赛影响
```

### 5.3 我的关注

- [ ] 增加最多 8 个 `favoritePlayerIds`，使用稳定 UUID 跨球队转会追踪。
- [ ] 球员详情和球星观察行提供统一的关注/取消关注按钮。
- [ ] 退役球员仍可从关注列表进入历史档案，但不占现役焦点名额。
- [ ] 关注列表展示伤停、转会、最近出场和下一个值得观察的赛程。
- [ ] 每次推进最多生成 2-3 条关注球员摘要，普通无事发生时保持安静。
- [ ] 关注偏好不写入 `GameWorld` 模拟数据，不参与 RNG 或比赛结果。

## 6. 权威比赛影响

### 6.1 不增加第二层球星 Buff

球星已经通过基础能力进入首发和球队单位质量。第一版的正确做法是让现有影响更准确、更具名，而不是再加“球星光环”：

- 教练阵型决定各位置首发人数和单位结构。
- 实际首发决定攻、中、守单位质量。
- 球员的边际贡献用“该球员与同位置下一可用替代者的单位质量差”计算。
- 比赛模型继续使用单位质量总结果；边际贡献只用于具名解释，不能再次叠加。
- 赛前最多展示全场 5 名关键人员及其真实作用，例如“某球员让锋线质量提升 2.3”，不要求主客数量对等。

### 6.2 事件归属改进

- [ ] 进球者继续使用 `goalScoring`、位置和关键战标签，并校准基础能力的有限权重。
- [ ] 助攻者至少使用位置与基础能力，不能只按位置权重随机分配。
- [ ] 定位球执行者使用位置、基础能力和已有进球倾向，不新增完整定位球属性。
- [ ] 关键扑救由实际在场门将及其能力参与，淘汰赛也必须走正确的时序。
- [ ] 门线封堵、拦截和解围继续只分配给实际在场且位置匹配的防守球员，并提高能力差异的可见度。
- [ ] 换人、红牌、伤停、加时、点球大战、转会分段和中立场继续服从实际出场快照。
- [ ] 事件归属使用独立派生随机源，尽量不改变既有比分随机序列。

### 6.3 淘汰赛关键防守

- [ ] 将 deny 处理移动到加时和点球决策之前，或整合进各比赛阶段的机会结算。
- [ ] 被扑救/封堵后应重新得到正确的常规时间或加时比分，再判断是否进入下一阶段。
- [ ] 点球大战继续独立，不把大战扑救混入常规扑救统计。
- [ ] 决赛中的门将和后卫能够产生可追溯的关键扑救/封堵事件，并参与 MOTM。

## 7. 统一的本场球员影响

建立一个纯函数，从权威事件、防守贡献和实际出场快照计算 `MatchPlayerImpact`。它是以下功能的唯一来源：

- MOTM。
- 球员最近 5 场近况。
- 直播焦点球员赛后总结。
- 球员详情的本场高光。
- 关注球员摘要和重大新闻候选。

第一版纳入：

- 进球、助攻和实际分钟。
- 普通扑救、关键扑救、面对射正和失球。
- 门线封堵、拦截、解围和在场失球。
- 黄牌、红牌以及是否直接影响比赛。
- 比赛重要性只能小幅影响叙事优先级，不应大幅改变纯表现评价。

约束：

- 防守动作按位置使用不同基准，不能让一次普通解围等价于进球。
- 解围数量设置收益上限，避免被长期围攻的失败方后卫仅靠数量当选最佳。
- 门将评价同时看扑救和失球，不能只奖励面对射正多。
- 胜方修正应明显低于当前 1.2 倍，个人表现优先于球队胜负。
- UI 第一版显示“决定性 / 出色 / 稳定”等影响档位和真实数据，不额外暴露伪精确的 0-10 单场评分。
- `seasonScore` 继续由赛季统计计算，不直接累加单场影响分，避免两套公式互相循环。

## 8. 直播焦点球员

### 8.1 选择规则

- 从本场实际首发中选择，替补席球星不会占据开场焦点。
- 全场最多 5 人，不要求主客数量对等；资格不足时不补普通球员。
- 优先级由基础能力、可信赛季表现、近期影响、本场边际阵容贡献和赛事重要性共同决定。
- 四个位置使用同一资格尺度，但展示理由按位置变化。
- 焦点选择在比赛开始前冻结，之后转会或能力变化不能改变历史回放。

### 8.2 焦点对位

两队都有焦点球员时只生成一个简短对位主题：

- 前锋 vs 后卫/门将：`矛盾对决`。
- 前锋 vs 前锋：`王牌对攻`。
- 中场 vs 中场：`中场主导权`。
- 其他组合：`核心对话`。

第一版不模拟持续人盯人或专属一对一事件；对位主题只总结双方真实比赛职责和值得观察的冲突。

### 8.3 视觉和播报预算

- [ ] 开场阵容完成后展示一次窄型“焦点对位”条，不能遮挡比分和主要控制。
- [ ] Canvas 对焦点球员使用一圈克制的细金环或小型标记，不使用大面积发光、头像悬浮或持续姓名牌。
- [ ] 姓名只在开场短暂出现，以及球员持球、扑救、封堵或直接参与关键事件时出现。
- [ ] 焦点球员被换下或罚下后立即停止场上标记。
- [ ] 一场比赛最多插入三次焦点专属叙事：开场、首次有意义参与、决定性事件或赛后总结。
- [ ] 普通传球和普通防守不强行播报球星姓名，避免信息噪声。
- [ ] 直播结束页展示双方焦点球员的真实贡献；没有关键表现时允许诚实显示“本场受到限制”。
- [ ] 减少动态模式、320px 宽度和低性能设备都保留可读标记，但允许关闭非必要动画脉冲。

## 9. 球员中心、详情与排行榜

### 9.1 信息架构

- [ ] 球员中心首屏增加“球星观察”，不是再增加一个横向排行榜页签。
- [ ] 世界焦点、新星雷达、我的关注使用紧凑列表或分段视图，不做嵌套大卡片。
- [ ] 榜单按“综合 / 进攻 / 组织 / 防守 / 历史”分组；具体榜单使用菜单或次级切换，避免移动端九个同级标签。
- [ ] 所有榜单明确当前赛季、全赛事或生涯范围，以及实际排序字段。

### 9.2 榜单规则

- 综合榜继续按 `seasonScore`，同时展示 `positionQuality`、出勤和可信度。
- 射手榜、助攻榜保留总数排序，并补充每 90 分钟、分钟和赛事级别作为比较语境。
- 创造力、防守榜和门将榜继续按位置表现质量，不退回原始总数堆叠。
- 生涯射手和生涯助攻只承担历史累计叙事，不与当季状态混用。
- 纪律榜保持事实统计，不参与球星资格加分。
- 不新增公开“球星榜”，世界焦点是有限编辑式观察入口，不是第十套评分体系。

### 9.3 球员详情

- [ ] 主卡继续明确区分基础能力和赛季综合分。
- [ ] 增加关注按钮、当前焦点身份、最近 5 次实际出场摘要和下一场关键赛程。
- [ ] 前锋近况包含进球、助攻与关键机会。
- [ ] 中场近况包含助攻、创造、进球和防守参与。
- [ ] 后卫近况包含封堵、拦截、解围、在场失球和零封贡献。
- [ ] 门将近况包含普通扑救、关键扑救、扑救率、失球和零封贡献。
- [ ] “位置之争”改为同时考虑基础能力、可信赛季表现和近期事实，不再主要依赖基础 rating。

### 9.4 奖项

- [ ] “最佳新星”改为真实 U23 资格，并使用赛季综合分、分钟可信度和赛事强度选择。
- [ ] MOTM 使用统一的本场影响，保证防守位置有真实获奖路径。
- [ ] 赛季最佳球员、最佳门将和位置奖继续使用现有跨位置/位置内评分，不再另造球星分。
- [ ] 赛季总结可以突出一名“赛季焦点人物”，但必须来自既有奖项或可解释表现。

## 10. 与教练阵型方案的共同架构

两套系统不应分别修改首发、比赛模型和 Canvas。推荐统一顺序：

```text
教练身份 + 比赛上下文 + 可用阵容
                 ↓
          本场阵型与策略
                 ↓
        按阵型选择实际首发
                 ↓
   位置单位质量 + 球员边际贡献
                 ↓
 权威比赛模型 + 焦点球员冻结快照
                 ↓
事件归属 / 统计 / MOTM / 赛前解释
                 ↓
战报 / 球员近况 / 直播阵型与焦点展示
```

共同约束：

- 教练战术和球星边际贡献只进入一次统一效果预算。
- 焦点球员选择必须发生在阵型首发确定后。
- 球星模块不反过来强迫教练使用某种阵型，也不增加手动核心角色。
- Canvas 同时消费冻结阵型和焦点快照，不再自行猜测站位或明星。
- 预测、正式模拟、自动推进和回放使用同一套纯函数与确定性输入。
- 赛前最多展示“一项战术观察 + 一组球星对位”，避免信息过载。

建议冻结的最小比赛数据草案：

```ts
interface FeaturedPlayerSnapshot {
  playerId: string;
  playerName: string;
  teamId: string;
  position: PlayerPosition;
  ratingAtKickoff: number;
  seasonScoreAtKickoff?: number;
  marginalUnitImpact: number;
  reason: 'ability' | 'form' | 'defensive-anchor' | 'creator' | 'finisher';
}

interface MatchPresentationSnapshot {
  homeTactics: MatchTacticsSnapshot;
  awayTactics: MatchTacticsSnapshot;
  featuredPlayers?: FeaturedPlayerSnapshot[];
}
```

字段名可在实现审计后调整；历史比赛缺少快照时不伪造球星对位。

## 11. 性能、存档与可维护性

- [ ] 球星资格、边际贡献和本场影响分别由纯函数计算，页面不复制公式。
- [ ] 所有阈值、位置名额和展示预算集中配置并写明校准来源。
- [ ] 当前比赛最多持久化五条焦点快照，不保存近况长文本。
- [ ] 关注列表最多 8 个 UUID，存储增长可以忽略。
- [ ] 旧比赛没有焦点快照时正常展示普通直播；不根据当前 rating 回填历史身份。
- [ ] 历史明细被压缩后仍保留既有 MOTM、奖项和荣誉，不要求永久保存每次普通触球。
- [ ] 焦点环复用现有 Canvas 绘制能力，不增加图片资源或逐帧 DOM 节点。
- [ ] 球星专栏使用记忆化选择器，不能在每次 Canvas 帧或滚动时扫描全部历史。
- [ ] 所有球星展示文案从原因代码和真实数据派生，禁止页面随机生成故事。

## 12. 测试与验收

### 12.1 单元与集成测试

- [ ] 四个位置都能产生长期能力 85+ 球员。
- [ ] 普通球员仍占主体，修复后不出现整体 rating 膨胀。
- [ ] 相同种子产生相同青训、焦点球员和事件归属。
- [ ] 世界焦点完整返回所有合格球员，低于资格线的球员不会因凑数入选。
- [ ] 新星雷达不读取或展示 `peakRating`。
- [ ] 关注 UUID 在转会后仍指向同一球员，退役后进入历史状态。
- [ ] 首发球星缺阵时不能成为直播焦点。
- [ ] 全场最多五名焦点球员，不要求主客数量对等，普通比赛允许零焦点。
- [ ] 助攻、定位球、关键防守的归属尊重能力、实际在场和位置。
- [ ] 淘汰赛关键扑救/封堵在加时和点球判断前正确结算。
- [ ] 统一本场影响能让高水平 GK/DF 合理赢得 MOTM。
- [ ] 解围堆积、短时间替补和失败方刷量不会轻易挤掉决定性贡献。
- [ ] 现有 `seasonScore` 公式、比分、积分、晋级、升降级和比赛确定性不被展示层改变。

### 12.2 长跑和平衡验证

- [ ] 比较初始世界与完全换代世界，评分分布、进球分布和球队实力层级仍然合理。

- [ ] 检查关注列表、焦点快照和比赛影响对 S150 存档体积的变化，目标不超过现有存档约 3%。

### 12.3 浏览器与视觉验证

- [ ] 在 `320x568`、`390x844`、`430x932` 和桌面检查球星观察、球员详情、榜单和直播。
- [ ] 检查 GK vs FW、DF vs FW、MF vs MF、FW vs FW 四种焦点组合。
- [ ] 检查单侧焦点、无焦点、替补、红牌、伤停、加时和点球大战。
- [ ] 焦点标记不得遮挡球、比分、事件字幕或其他球员姓名。
- [ ] 动态播报仍可滚动到最新消息，焦点播报不能挤掉权威事件。
- [ ] 移动端不出现横向溢出、榜单标签拥挤或长姓名不可辨认。
- [ ] Canvas 性能保持现有预算，减少动态模式无闪烁或持续脉冲。
- [ ] 浏览器控制台无新增错误和警告，音效不会因焦点事件重复播放。

## 14. 最终体验验收

功能完成后，玩家应当可以在一分钟内回答：

1. 这个时代最值得关注的几名球员是谁，他们分别强在哪里？
2. 哪些年轻人已经凭真实表现进入公众视野？
3. 我关注的球员最近是否出场、受伤、转会或完成了关键表现？
4. 这场关键比赛双方最值得观察的人是谁，为什么？
5. 教练的阵型如何放大或限制了这些球员的作用？
6. 直播中的高亮是否对应真实首发、触球和关键事件？
7. 门将或后卫能否凭个人表现成为比赛主角，而不是只能依赖球队零封？
8. 玩到第 20、50 或 100 季时，世界是否仍持续产生少量真正的新球星？

只有同时满足“长期有人可追、比赛确实受影响、画面适度可见、赛后能够回顾”，球星存在感模块才算完成。
