这份清单负责《足球联赛宇宙》下一阶段的玩法、故事、操作反馈和参赛体验打磨。它不替代已有的 `data-chain-optimization-checklist.md` 与 `ui-polish-checklist.md`：

- 通用视觉规范、移动端基础体验和资产预算继续由 UI 清单约束。
- 本清单只追踪“观察者为什么在意、能做什么、世界如何回应、历史如何沉淀”。
- `contest-final-polish-checklist.md` 记录参赛打磨的历史执行顺序，并继续维护真人盲测、投稿材料和最终候选版本的发布门禁。

**勾选规则：实现不等于完成。只有功能、数据语义、自动化测试、桌面/移动端浏览器体验和性能验证全部通过后，才能将条目标记为完成。**

## 0. 已冻结的产品方向

- [x] 玩家身份是足球宇宙的上帝视角观察者和历史见证者，不是经理或教练。
- [x] 核心乐趣是观察球队、球员、教练、赛事和王朝随时间自然演化。
- [x] 玩家可以选择关注对象、做出判断、控制时间和回看历史，但不负责阵容、战术、训练和日常经营。
- [x] 所有关注、预测、故事和展示层功能不得暗中改变比赛结果。
- [x] 比赛结果继续由可复现的种子模拟产生；解释层必须引用真实模型因素或真实事件，不得编造因果。
- [x] 默认球队和教练名称当前保持不变，继续服务个人游玩体验。
- [x] 自定义球队入口继续保留，不因参赛体验改造而隐藏或降级。
- [x] 投稿所需原创名称与资产未来通过独立的“参赛宇宙预设”处理，不复制模拟引擎，也不覆盖个人经典宇宙。
- [x] 不引入后端、强制联网、付费系统或 AI 运行时依赖。

## 1. 目标体验与验收基线

### 1.1 核心循环

- [x] 将每个关键轮次稳定收束为：`关注故事 -> 赛前判断 -> 观看/揭晓 -> 理解结果 -> 故事与历史推进`。
- [x] 不观看直播的玩家也能在一次普通推进后获得完整的结果、解释和故事反馈。
- [x] 观看直播的玩家获得更强氛围和事件过程，但不会获得影响赛果的额外权限。
- [x] 每个首屏最多保留一个主要操作，其他功能保持次级，不与推进争夺注意力。
- [x] 普通轮次可以快速完成，关键比赛才使用完整动画与更强叙事节奏。

### 1.2 前五分钟目标

- [x] 新玩家在 30 秒内理解“我不操控球队，我观察一个自动演化的足球世界”。
- [x] 新玩家在 60 秒内进入宇宙，并完成关注球队或“纯观察”选择。
- [x] 新玩家在 2 分钟内看到一场明确的焦点比赛、赛前概率和真实影响因素。
- [x] 新玩家在 3 分钟内完成一次观察判断并看到比赛结果。
- [x] 新玩家在 4 分钟内理解预测为何命中或落空，以及比赛是否属于爆冷。
- [x] 新玩家在 5 分钟内看到至少一条故事或观察主题发生变化。
- [x] 首次体验不依赖玩家主动寻找隐藏页面，也不要求阅读长篇教程。

### 1.3 十五分钟容量

- [x] 设计一条可重复验证的 15 分钟评审路线，覆盖至少两个普通轮次、一个关键比赛和一次阶段性故事更新。
- [x] 15 分钟内让玩家看到球队、球员或教练至少一个可感知的状态变化。
- [x] 15 分钟结束时提供可继续游玩的悬念，而不是一次性演示结束页。
- [x] 推荐体验和自由长期游戏共用同一套真实模拟规则，不为演示伪造固定结果。

- [x] 覆盖球队基础能力、可用阵容、伤停损失、士气、疲劳、势头、主客场、教练和赛事适性。
- [x] 每场最多显示三项最有区分度的因素；接近零的因素不占位置。
- [x] 同类因素合并，避免同时出现三条都在描述阵容实力。
- [x] 因素文案使用区间和自然语言，不公开足以让玩家反推完整公式的内部小数。
- [x] 预测和正式模拟对同一 fixture、阵容与窗口使用完全一致的输入快照。

- [ ] 从真实事件中识别红牌、伤退、领先被逆转、绝平、绝杀、加时和点球大战。

## 6. P1 连续故事导演

### 6.1 最小故事模型

- [x] 定义轻量 `Storyline`，只保存故事类型、参与对象、开始窗口、当前阶段、证据、最近更新和结局。
- [x] 故事阶段限定为 `出现 / 发展 / 高潮 / 落幕`，不建设通用剧情脚本语言。
- [x] 每个世界最多同时突出一条主要观察故事和一条全局故事。
- [x] 同一球队同类故事设置冷却和迟滞条件，避免一轮出现、下一轮消失。
- [x] 故事检测完全确定性；AI 未来最多润色文案，不负责判断故事是否发生。
- [x] 活跃与已结束故事有明确存储上限，保持长期存档预算。

### 6.2 第一批三类故事

- [ ] 黑马崛起：结合赛季前预期、球队实力、当前排名、积分差和关键胜利。
- [ ] 豪门危机：结合声望/预期、排名偏差、连败、教练压力和关键赛事出局。
- [x] 升班马求生：结合上赛季升级记录、保级线、阶段排名和最终结果。
- [x] 每类故事都定义触发、升级、降温、成功结局和失败结局。
- [x] 每类故事至少准备 6 个固定种子或构造场景测试，覆盖边界条件和赛季结束。
- [ ] 暂缓黄金一代、宿敌复仇、复杂球员传记和多球队交叉剧情。

### 6.3 故事呈现

- [x] Dashboard 只显示故事当前章节、证据和下一观察点，不展示长篇小说。
- [x] 新闻系统在故事升级或结局时提升优先级，普通轮次不重复播报同一句话。
- [x] 关键比赛卡显示它与当前故事的关系，例如“保级转折战”或“黑马试金石”。
- [x] 赛季回顾总结故事起点、关键节点和结局。
- [x] Chronicle/History 只增加紧凑故事时间线，不进行大规模职责重写。
- [x] 故事文案始终可由数据证明，避免使用“管理层震怒”等无来源事实。

## 7. P1 历史沉淀与回看价值

### 7.1 本轮到赛季

- [x] 每次推进后生成一份紧凑“世界回应”，只包含关注结果、判断结算和关键变化。
- [x] 普通结果可以折叠，重要比赛和故事节点自动突出。
- [x] 赛季回顾加入主要观察球队四段轨迹、当季判断记录和已有故事结局。
- [x] 观察主题上线后，将主题结果并入同一主要观察档案。
- [x] 赛季回顾可跳转到相关球队、关键球员和赛季主教练。
- [ ] 补充相关比赛与奖杯详情跳转；当前比赛历史只保留近 3 季，不伪造长期入口。
- [x] 不复制现有统计，只保存无法由历史记录稳定重建的最小叙事元数据。

### 7.2 长期历史

- [ ] 在历史页提供按赛季查看的“这个宇宙发生了什么”摘要。
- [ ] 支持查看球队王朝、连续升级/降级、重大爆冷和故事结局。
- [x] 主要观察球队发生变化后，过去赛季的关注记录保持原样。
- [ ] 上帝之手干预作为历史事件可见，但不污染自然宇宙的统计定义。
- [x] 继续执行存储压缩和历史上限；新增元数据不得破坏既有 S150 长期预算。
- [x] 运行至少 10 赛季语义审计和 150 赛季存储预算测试。

## 8. P1 球队与教练身份表达

- [ ] 从现有球队属性、转会倾向和历史表现派生 1-2 个球队身份标签。
- [ ] 第一批标签控制在青训工厂、巨星策略、防守堡垒、疯狂进攻、稳定豪门、杯赛专家等少量集合。
- [ ] 从现有教练 style、攻防加成、风险偏好、稳定性和杯赛能力派生教练标签。
- [ ] 标签必须在比赛模型或转会决策中有真实依据，不添加纯装饰人格。
- [ ] 球队详情、赛前解释、转会新闻和教练详情使用相同术语。
- [ ] 身份变化只在真实属性或长期成绩跨过稳定阈值后发生，避免频繁跳动。
- [ ] 不新增球员训练、战术面板、合同谈判和经理控制项。

## 9. P1 操作便捷性与反馈

### 9.1 时间控制

- [x] 保留推进一轮作为最明确的基础操作。
- [x] 增加或统一“前往下一关键节点”，并明确它将跳过哪些窗口。
- [x] 有未结算观察判断、关注球队关键比赛或故事高潮时，不允许无提示跳过。
- [x] 快速推进后的摘要不超过一个移动端视口，并可展开查看完整结果。
- [x] 直播提供 `精华 / 1x / 3x`，默认速度通过真实设备体验测试确定。
- [x] 页面隐藏、切后台和 reduced-motion 状态继续暂停非必要动画。

### 9.2 移动端与名称表达

- [x] 主要推进操作始终位于安全区内，不遮挡导航、比分和正文。
- [x] 紧凑比赛组件优先显示球队简称；详情与可展开区域显示完整名称。
- [x] 禁止将球队名截断成无法区分的单字或无提示省略号。
- [x] 主要操作和关键图标保持至少 `44x44px` 触控区域。
- [x] 320px、390px、430px 宽度下无页面级横向滚动、重叠和按钮文字溢出。

### 9.3 反馈层级

- [x] 点击后 100ms 内出现按压/加载反馈。
- [x] 普通轮次结果在约 1 秒内完成主要揭晓；关键比赛允许更长但可跳过。
- [ ] 判断命中、爆冷、故事升级和赛季结束使用不同但克制的视觉/声音反馈。
- [ ] 错误、禁用、空状态、加载、成功和离线恢复均有可理解的界面状态。
- [ ] 不使用 Toast 堆叠代替页面内长期可见的信息。

## 10. P2 参赛视觉与声音打磨

### 10.1 第一观感

- [ ] 为开始观察页面制作一张原创主视觉，直接表现足球世界、时间和历史感。
- [ ] 首屏品牌、开始操作和观察者定位在 30 秒内可理解。
- [ ] 减少功能性 Emoji 和临时渐变装饰，使用统一图标、球队徽章和赛事资产。
- [ ] 保持“夜间足球转播台”方向，但增加草地、奖杯、历史纸张和球队色等多类视觉信号，避免单一深蓝界面。
- [ ] 首屏资产在移动网络与冷启动下满足既有 `150KB` 首视口预算。

### 10.2 比赛与故事资产

- [ ] 完成直播记分牌、比赛阶段、关键事件和命运偏差的统一视觉语言。
- [ ] 为黑马、危机、求生三类故事制作可复用章节标记或小幅插图。
- [ ] 为赛季回顾和宇宙档案设计一张可分享但仍可访问的总结卡。
- [ ] 视觉资产不烘焙球队名、比分和中文正文；真实文本保留在 DOM。
- [ ] 所有装饰资产提供 reduced-motion、低性能和加载失败降级。

### 10.3 声音反馈

- [x] 只设计开场、进球、爆冷、故事升级和赛季结束等少量关键声音。
- [x] 浏览器首次用户手势后再启用声音，避免自动播放限制和突兀发声。
- [x] 提供全局静音并记住选择。
- [x] 声音关闭后仍有完整视觉反馈；不把信息只放在音频中。

- [ ] 桌面与移动端真实浏览器流程经过检查并保留可复查证据。

- [ ] `progress.md` 与本清单记录了实现内容、验证证据和仍未完成的范围。
