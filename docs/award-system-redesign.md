# 评奖系统重设计（第一期：算法 + 奖项风向）

状态：算法与「奖项风向」面板已实施，经 3 种子 × 30 季端到端审计。范围仅限评奖算法与风向面板；球员中心整体重构留到第二期。

## 为什么要改

v4.62.0 的评奖在一次实测里暴露了三类问题：一个联赛杯 + 超级杯双冠王，五项个人奖加最佳教练无一入选，而射手王却出自该队。

1. **球队成就几乎不进个人奖。** 只有金球奖有团队乘子；最佳后卫 / 最佳门将 / 最佳新星 / 赛季综合表现 / 射手王全部是纯个人分。
2. **杯赛荣誉只认洲际杯。** `season-end.ts` 传给评奖的 `continentalCupWinners` 只有大陆杯 / 南方杯 / 东方杯，而这三个杯 `firstSeason: 5, interval: 6`，六年才一届。联赛杯和超级杯冠军对个人评分贡献为零。
3. **同一个"最佳"有三份互不一致的实现。** 射手王新闻与金靴奖用 `playerStats` + 严格 `>`（先到先得），赛季回顾的射手王卡片用 `playerStatsHistory` + 进球→助攻→出场。进球并列时三者必然分歧。
4. **层级口径互相矛盾。** `seasonScore` 里联赛强度只占 10% 权重、跨度 10 分（顶级 100 / 甲级 95 / 乙级 90），实际只值 1 分；金球再乘 ×0.90 / ×0.78 构成双重折扣；金靴完全无系数；最佳后卫 / 门将硬性锁死顶级联赛。同一个乙级球星被三套规则分别对待。
5. **最佳教练惩罚强队。** `expectedPos = round(16 × (1 - (expectation - 1) / 4))`，expectation = 5 的三支豪门 expectedPos = 0，夺冠超额值为 −1，数学上永远拿不到该奖。
6. **前锋和中场没有位置奖。** 只有最佳后卫 / 最佳门将，中场球员在评奖体系里没有任何位置路径。

## 不可预判如何做到（不加随机）

评审结论：**奖项本身保持 100% 确定性**，不引入任何抽签。理由：

- 产品契约要求叙事只解释模拟事实，不改写结果；评奖属于模拟结果。
- RNG 流是承重墙。杯赛阶段 1 给超级杯加 pots 分档后，一次洗牌变四次，整个赛季构建的随机流错位，20 个候选种子里没有一个还能满足开局断言，推荐种子被迫从 20260709 换到 20260722。在颁奖时插一次抽签会让这类审计全部作废。

不可预判由三个诚实机制叠加产生：

1. **热度公式与评奖公式不同。** 风向卡用 `buzz = 0.5×赛季分 + 0.3×近 5 场状态 + 0.2×球队近 6 场势头`；评奖用全季聚合 + 最终联赛排名。两者本就不是一回事。
2. **阈值带代替名次。** 相邻候选 buzz 分差超过 `BAND_WIDTH` 才另起一档，档内按球队名排序而非分数。卡片只显示「最被看好 / 有力竞争 / 黑马」三档，不显示任何数字与名次。这既诚实（他们确实接近），又消掉了"第一就是冠军"的读法。
3. **最大变数本来就未揭晓。** 金球乘子里权重最高的是最终联赛排名（冠军 ×1.18 / 前四 ×1.08 / 后四 ×0.94）。第 16 轮时排名仍可大洗牌——即使把真实评分原样贴出来也预测不了第 30 轮。

跑火车的情况不隐藏：唯一领跑者且与次席差距超过 `RUNAWAY_GAP` 时，卡头标记「一人领跑」。那种情况玩家本来也算得出来，藏它没有意义。

## 两个进球荣誉：口径必须分开

### 起点：一次分母用错的实现

第一版把金靴写成「进球 × (30 / 联赛轮次) × 系数」。审计跑完 90 季才发现分子分母根本不是同一批比赛：

`updatePlayerStatsAndSegmentsFromResults` 接收整个窗口的 results，`buildMatchStatDeltas` 不做赛事过滤，所以 `playerStats.goals` 是**全赛事**总数——实测 26% 的进球来自联赛之外（超级杯小组赛 10.5%、联赛杯 6.8%、环球杯 3.5%、洲际杯 2.1% 等）。而分母除的是**联赛**轮次。

实测各层级全赛事场均出场：L1 **34.1** 场、L2 **18.8** 场、L3 **15.9** 场。真实赛程比是 L2 **1.81**、L3 **2.14**，而实现统一用了 30/14 = **2.14**——L2 被多算了 18%。第一版报出的「低级别 29%」里，有一部分正是这个错误分母的产物。

### 拆成两个荣誉

| | 金靴奖 | 射手王 |
| --- | --- | --- |
| 口径 | **全赛事**进球 | **纯联赛**进球 |
| 赛程归一 | 不做 | `(30 / 联赛轮次) ^ 1.0` |
| 理由 | 杯赛征程是挣来的，不是结构性差异 | 分子分母同为联赛，折算才成立 |
| 实测低级别占比 | **0%**（60/60 顶级） | **38%** |
| 场均获奖进球 | 30.4（全赛事） | 19.7（联赛） |

两者在约 **72%** 的赛季里颁给不同球员。这不是 bug，是设计——它们测量的本来就是两件事。旧版本三份「进球最多」实现互相矛盾的问题也由此消失：现在答案不同是理所当然的。

**金靴为什么不做赛程归一。** 它的分子包含杯赛，而分母只知道联赛轮次，任何归一都会重蹈第一版覆辙。要归一就得引入「各层级全赛事场均出场」这类实测常数（34.1 / 18.8 / 15.9），而这些数会随杯赛赛制改动漂移——用可维护性换一个本不属于这个奖的公平性。

**金靴的系数不承重。** 60 季审计中，加与不加系数结果完全一致，因为全赛事赛程差（34 vs 19 场）远大于任何合理折扣。保留它是为了与射手王共用一张表、并表达正确意图，而不是因为它今天能改变结果。低级别的通道在射手王那边。

### 杯赛进球其实是顶级的结构性优势

一个反直觉的实测结论：把杯赛进球从进球荣誉里剔除，**低级别占比反而上升**（0% → 38%）。因为顶级球队踢更多杯赛、走得更深，球员能刷到低级别球员拿不到的额外进球。剔除杯赛等于拆掉这个优势。

### 射手王的赛程归一

顶级 30 轮，甲级 / 乙级各 14 轮。纯联赛口径下，原始进球测的仍是「谁踢的比赛多」：

| | 场均联赛进球 | 轮次 | 每轮进球 |
| --- | --- | --- | --- |
| 顶级 | 30.9 | 30 | 1.03 |
| 甲 / 乙级 | 17.6 | 14 | **1.26** |

**折算成每轮，低级别射手反而高 22%**——原始进球测的是「谁踢的比赛多」，不是「谁更会进球」。不做归一时低级别只有 5% 的获奖率。

```
射手王分 = 联赛进球 × (30 / 联赛轮次) ^ 1.0 × 联赛系数
           └──── 结构性修正，不含判断 ────┘   └─ 唯一的质量判断 ─┘
```

**指数固定 1.0。** 赛程长度不携带任何球员质量信息，不该决定荣誉。这是公平修正，不是对低级别让步。记录墙早就用 `bestRate` 表达过同一条原则（`season-records.ts`：「Raw "most wins" style records were structurally monopolised by the top flight」），射手王只是补上了这一步。

**系数为什么必须低于 0.90。** 审计发现 0.90 / 0.80 实测恰好是**层级中立值**——该设定下低级别拿到 52%，几乎正好等于其 16/32 的球队占比，精确抵消了低级别每轮多进 22% 的效率优势。想表达任何偏好，必须低于 0.90。

实测（3 种子 × 30 季）：

| L2 / L3 系数 | 低级别获奖率 | 乙级单独 | 种子间波动 |
| --- | --- | --- | --- |
| 0.90 / 0.80 | 52% | 11% | 37%–63% |
| 0.80 / 0.65 | 36% | 3.3% | 20%–43% |
| **0.75 / 0.58** | **29%** | **2.2%** | 17%–37% |
| 0.70 / 0.50 | 17% | 0% | 13%–20% |
| 0.65 / 0.45 | 10% | 0% | 7%–13% |

**选定 0.75 / 0.58**。纯联赛口径下实测顶级约 62%、甲级约 32%、乙级约 7%——第三级联赛拿射手王是稀有事件，不是常态。

**关键不变量。** 在测试过的全部系数下，获奖者的进球效率始终是**本联赛均值的 5.2–5.6 倍**，18 组数据几乎不动。调系数只改变「怪物来自哪个联赛」，不会让奖项退化成「弱联赛刷数据」。质量有硬下限——这正是敢把它做成可调旋钮的前提。

审计脚本可复现以上全部数字（均支持 `SEASONS` / `SEED` 环境变量）：

- `scripts/audit-award-distribution.ts` — 端到端七奖层级分布
- `scripts/probe-goal-sources.ts` — 按赛事类型统计进球来源与各层级实际出场
- `scripts/audit-golden-boot-basis.ts` — 三种分母口径对比
- `scripts/audit-scoring-split.ts` — 分拆方案预测
- `scripts/verify-scoring-split.ts` — **读引擎实际产出**验证两个荣誉
- `scripts/audit-golden-boot-normalisation.ts` / `-coefficient.ts` — 指数与系数扫描
- `scripts/probe-golden-boot.ts` — 逐例核对获奖者

| 成就 | 金球 | 位置奖 |

| 后四 | ×0.94 | ×0.97 |

| 世界杯冠军 | ×1.15 | — |
| 联赛杯冠军 | ×1.05 | — |

国内杯合计设上限，使双冠（1.1025）不超过洲际杯（1.10），保持洲际杯的含金量。

### 位置奖构成

```
positionAwardScore = positionQuality
                   × availabilityFactor    // 0.85 + 0.15 × 出勤分/100
                   × 层级系数
                   × 团队系数
                   × 样本门槛              // ≥1800 分钟 1.00 / ≥1200 0.95 / 否则 0.85
```

用 `positionQuality`（纯位置产出，层级中立）而非 `seasonScore`，避免与显式层级系数构成双重折扣。出勤以轻量因子进入，因为 `positionQuality` 本身不含出勤。

### 金球

`seasonScore` 含 10% 权重的联赛强度，与显式层级系数重复。评奖改用**层级中立分**：

```
tierNeutralScore = seasonScore + (100 - leagueStrength) × 0.10
```

这是精确还原（把 leagueStrength 代入 100），不改 `seasonScore` 本身，因此已归档赛季的 `performanceSnapshot` 继续有效。

### 公式与展示

```
金靴分   = 全赛事进球 × 联赛系数
射手王分 = 联赛进球 × (30 / 联赛轮次) × 联赛系数
```

平局顺序统一为 **评分 → 原始进球 → 助攻 → 出场 → uuid**。射手王的新闻行与赛季回顾卡走同一套评分与同一套平局链，因此不可能再各说各话。

展示上把该写的算式写出来，并且**每个数字都标明口径**——两个荣誉并存时，一个不写口径的「34球」根本无法分辨是哪个：

- 金靴：`全赛事 34球` / `全赛事 30球 × 0.75 = 22.5`
- 射手王：`联赛 25球` / `联赛 16球/14轮 → 折算34.3球 × 0.75 = 25.7`

射手王多了一步换算，「玩家能自己复算的荣誉才可信」这条原则在这里不是变松了而是变紧了——不写出来就是在要求玩家相信一个黑箱。

风向卡只覆盖七个正式奖项，因此只出现金靴，用同一套文案（`全赛事 34球 · 2助`）。折算值是公开的奖项算术，不是风向内部状态——玩家本来就能从球员中心排出射手榜，暴露它不泄露任何风向依赖的信息。

### 新星

保持简单可读：**层级中立分 × 新星层级系数 × 样本门槛**，U23，排除同赛季已获其他奖者。

刻意**不**加入"突破性"权重——那会让奖项难以解释（"为什么 78 分赢了 80 分"）。赛季间的进步改由风向卡作为**展示上下文**呈现（"上季 65 → 本季 78"），不进入评奖公式。叙事放在展示层，判断放在公式层。

### 最佳教练拆两个

- **冠军教头**：顶级联赛冠军队教练，始终展示。
- **最佳教练**：保留超额完成预期公式，但排除冠军队，避免同一人出现两次。

强队由此获得承认，同时不破坏"超额"这个概念本身。

## 新增奖项

`best_forward`（最佳前锋）、`best_midfielder`（最佳中场），与最佳后卫 / 最佳门将同构：限顶级联赛，按位置奖公式排序。

### 存档兼容

`save-schema.ts` 的奖项类型白名单扩展为接受 7 种类型。旧存档只有 5 种，仍然通过校验——新增是**加法**，不需要升 `SAVE_SCHEMA_VERSION`，现有存档不丢。

已归档赛季的旧奖项是在旧规则下算出的，属于历史记录，不回溯重算。

## 奖项风向面板

### 出现条件

顶级联赛已赛场次 ≥ `BUZZ_START_ROUND`（16 / 30）时出现，挂在球员中心顶部。每轮推进后更新。

### 内容

7 张卡对应 7 个引擎奖项。每卡最多 5 名候选，分 3 档。卡头显示「第 N 轮形势 · 剩余 M 轮」。

每名候选显示：姓名、位置、球队、**球队当前联赛排名**（明确标注非最终）、本季关键数据（按奖项不同）、已有生涯荣誉（如「2届金球」）。

**不显示**：buzz 分数、名次、任何可排序的数值。

### 热度公式

```
buzzScore = 0.50 × 层级中立赛季分
          + 0.30 × 近 5 场状态分     // clamp(45 + 平均影响 × 8, 0, 100)
          + 0.20 × 球队势头分        // 近 6 场积分 / 18 × 100
```

近 5 场状态复用 `buildRecentPlayerForm`，它本身只保留每名球员最近 5 场样本。状态分的换算沿用 `star-presence.ts` 里 `recentPriority` 的既有约定。

## 实测分布（3 种子 × 20 季 = 60 季，读引擎实际产出）

由 `scripts/verify-scoring-split.ts` 与 `scripts/audit-award-distribution.ts` 读引擎实际颁出的奖，不是事后重算。

| 荣誉 | 口径 | 顶级 | 甲级 | 乙级 | 低级别占比 | 场均获奖进球 |
| --- | --- | --- | --- | --- | --- | --- |
| **射手王** | 联赛 | 37 | 19 | 4 | **38%** | 19.7 |
| **最佳新星** | — | 51 | 6 | 3 | **15%** | — |
| 金靴奖 | 全赛事 | 60 | 0 | 0 | 0% | 30.4 |
| 金球奖 | — | 60 | 0 | 0 | 0% | — |
| 最佳前锋 / 中场 / 后卫 / 门将 | — | 60 | 0 | 0 | 0% | — |

- **两个进球荣誉在 72% 的赛季里颁给不同球员**（60 季中 43 季）。这是设计意图，不是分歧。
- **金球奖 67% 出自冠军球队**（40/60）。国内杯乘子与团队系数确实起作用了——这正是最初「双冠王颗粒无收」要修的东西。
- **低级别两条通道都通**：射手王 38%、新星 15%。金靴 0% 是刻意的——全赛事口径下顶级球队踢更多杯赛、走得更深，这个优势是挣来的。
- **金球与四个位置奖 100% 顶级**。位置奖是刻意的（后卫 / 门将历来如此）。金球不是硬锁，但层级中立分 ×0.90 加上「低级别球队永远拿不到冠军 / 前四乘子」，实际差距约 1.31 倍。这符合「世界最佳球员在最高级别联赛踢球」的直觉，但如果后续希望金球也偶尔下沉，这是下一个要动的旋钮——不是本次范围。

### 逐例核对

射手王的低级别获奖者全部核对过，确认每个人的每轮产量都高于当年顶级最佳（`verify-scoring-split.ts` 自动打印）：

| 赛季 | 获奖者 | 获奖线 | 当年顶级最佳 |
| --- | --- | --- | --- |
| S4 | 胶州港湾 | 16球/14轮（1.14/轮） | 22球/30轮（0.73/轮） |
| S11 | 小台北 | 19球/14轮（1.36/轮） | 23球/30轮（0.77/轮） |
| S17 | 辽宁队 | 22球/14轮（1.57/轮） | 17球/30轮（0.57/轮） |

没有一例是「弱联赛刷数据压过真射手」。脚本另外守住一条不变量：联赛进球永远不超过全赛事进球（60 季 0 例违例）。

### 一处与本次改动无关的既有观察

顶级射手王场均约 30 球（区间 21–49），即场均约 1.0 球——远高于现实足球的顶级射手（约 0.8）。这是模拟既有的进球模型特征，**不是本次改动引入的**：改动前的审计同样是均场 31.15 球。若要校准，属于比赛模拟层，不在评奖范围内。

## 不做什么

- 不在奖项结果里引入随机或抽签。
- 不升 `SAVE_SCHEMA_VERSION`，不回溯重算已归档赛季的奖项。
- 不改 `seasonScore` 本身——球员页、生涯榜、转会身价、叙事扫描都在读它。
- 不动参赛版。
