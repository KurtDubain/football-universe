# 直播画面重做：转播机位、体育场、主场特色、情绪

日期：2026-11-17 · 分支 `feat/youth-balance`

提交：`15cd4f6` 运动修复 → `f3cf0cc` 转播机位 → `8c28e7c` 体育场 →
`7c24374` 主场特色 → `8587716` 情绪 → `8f0201e` 实机微调

## 起点

用户原话：「现在让人不觉得特别想看，还是没那么真实，运球之类的，有的时候
感觉很一卡一顿的」。

这句话里是两个问题混在一起：

1. **运动层卡顿** —— 可以测量。先把它变成数字，再修。
2. **画面不像一场比赛** —— 不可测量，只能靠并排对比和实机观感。

方案分五层。第 0 层修运动，第 1–4 层重做画面。

## 前提：物理层与视角无关

整个方案成立的前提是一条已有的性质：球场坐标全部是归一化的 0–1。
换视角只改投影，不动 `physics.ts` / `sequence.ts`。

这条前提也是 `docs/match-live-polish-plan.md` 第 7 节「不做视角切换」被
推翻的原因 —— 那个判断假设换视角要重写运动层，实际上运动层一行未改。

## 第 0 层 运动修复（`15cd4f6`）

先测量，再改。诊断手段：逐帧记录球速与球员速度，统计静止占比、最长冻结
帧数、速度分位数。

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 球静止时间占比 | 17.4% | 0.6% |
| 球员速度为零占比 | 18.5% | 7.0% |
| 单次最长冻结 | 14 帧 | 5 帧 |
| 速度 p25 / p50 | 15% / 58% | 30% / 82% |

四处改动：

- `MIN_CRUISE_FRACTION = 0.35` 巡航下限。**保留原斜率 `PURSUIT_GAIN = 0.11`**
  —— 斜率是照真实画面调出来的，只加下限不改斜率，原有断言无需修改即通过
- `idleDriftOffset` 落位微动，跳过硬吸附
- 持球触球循环
- 定位球助跑 `setPieceRunUpTarget`。早前豁免「防守墙不该晃」导致 20 名
  球员在角球助跑全程冻结

## 第 1 层 转播机位（`f3cf0cc`）

新增 `projection.ts` / `broadcast-view.ts` / `broadcast-pitch.ts` /
`broadcast-figures.ts`。三机位：`tactical` / `sideline` / `box`。

```
tactical  far 0.19 / near 0.98 / span 1.04 / ratio 0.82 / center 0.5
sideline  far 0.27 / near 1.00 / span 1.32 / ratio 0.70 / center 0.5
box       far 0.31 / near 1.04 / span 2.45 / ratio 0.56 / center 0.79|0.21
```

关键决策：

- **机位切换是硬切不是移动** —— 真实转播就是切镜头，而且最省
- **草皮改为每帧程序化绘制，弃用位图缓存** —— 几百条 path 相对 22 个
  球员可忽略，换来任意缩放下线条锐利 + 换镜头无需重烘
- **人是立绘不是圆点** —— 俯视椭圆在相机下立刻露馅：背对镜头跑动的人
  应该变窄。全身尺寸都从「身高像素」一个数推出来，`profile = |dirX|`
  一个数决定身体宽窄
- **球和球员同一条深度序列** —— 防守球员可以站在球前面，是平面球场给
  不出的最强景深线索
- **竖屏用屏幕方向向量而不是分支** —— `BroadcastView.up/right` +
  `withUpright`，屏幕上方始终是屏幕上方

### 唯一一个「先测量再改」抓到的真 bug

机位不能只按「时刻」选。实测发现 `finish` 覆盖三十米外的射门、
`outcome` 再 hold 一秒多，只按时刻会把 2.45x 镜头架在中圈而球门在画面外。
加了 `BOX_CAMERA_REACH = 0.26`（27 米）位置闸门。

## 第 2 层 体育场外壳（`8c28e7c`）

新增 `broadcast-stadium.ts`。远端看台、观众、顶棚灯带、广告板。

- **看台离屏烘焙一次后 `drawImage` 平移 blit** —— 平移相机是移动背景
  图层，不是重画几千个座位
- **座椅按区块上色，观众才是噪点层** —— 第一版把座位颜色随机撒，整片
  看台变成电视雪花。真实看台是按区块统一色的座椅 + 杂色的观众，两层
  必须分开
- 下层座椅取主场色、上层压暗，块间亮度抖动
- 顶棚 12 条灯带。**光晕半径按看台高度而不是宽度** —— 禁区机位下看台宽
  近两倍画布，按宽度算会把整帧洗白

### 改掉的两处

- 看台和广告板各用一套平移公式，`centerX` 偏离 0.5 时两者错位（禁区机位
  最明显），统一成 `frontCenter`
- `BROADCAST_SURROUND_COLOR` 从 `broadcast-pitch.ts` 移到 `broadcast-view.ts`，
  `drawBroadcastPitch` 不再填画布（改由 stadium 填）

## 第 3 层 主场特色（`7c24374`）

### 队徽改成单一数据源

队徽原本是 SVG。canvas 的 `Path2D` **直接吃 SVG path 字符串**，所以同一份
字符串能同时驱动 React 徽章和 canvas 绘制。

抽出 `src/components/team-badge-geometry.ts`，`TeamBadge.tsx` 改为消费它，
canvas 侧新增 `team-crest.ts`。中圈草皮上的队徽、tifo 上的队徽因此必然和
球队列表里的一致 —— 两份手维护的副本一周内就会漂移。

`teamBadgeParts` 有测试：400 个俱乐部覆盖全部 6 种外框 / 12 种符号 /
4 种底纹。

### 接线

- **中圈队徽**画在草皮条纹之上、标线之下，颜色向白混 50% —— 草皮上的
  队徽是喷绘的浅色痕迹，不是饱和色贴纸。`flatten` 参数按中圈投影后的
  长短轴压扁，方形队徽贴在透视草皮上会像浮在上面的贴纸
- **tifo**：一条看台挂主场色横幅 + 深色队徽 + 褶皱，位置避开中央大屏。
  白徽画在主场色布上没有对比度去画图案，会读成一个空白圆盘
- **大屏**：比分 + 分钟 + 两队色条。尺寸按看台高度而不是宽度；横向位置
  钳进画面 —— 被画面边缘切一半的比分牌读起来像 bug 不像建筑
- **球衣图案**取队徽底纹编号，同色球队靠图案区分；九像素以下不画条纹
- **广告板**加两道浅色文字条 —— 纯色格远看像一排积木，有字才像广告牌

### `live-score.ts`

按分钟算实时比分。`own_goal` 记给受益方、点球大战不计入 —— 口径抄
`goalFacts` 而不是重新发明：转播比分牌和最终结果不一致会是整个功能里
最显眼的 bug。

## 第 4 层 情绪（`8587716` + `8f0201e`）

- **观众闪光灯**：进球时看台上一片手机亮起。这是真实球场最容易被认出来
  的一个动作。用缓存的白色光晕精灵 `drawImage`，不是一堆
  `createRadialGradient` —— 一次庆祝最多同屏六十个。位置每三帧重掷；
  位置停住一秒就不像闪光了
- **主场色光晕**：进球时从看台底部往上洗一层主场色
- **`broadcast-grade.ts`**：整帧调色 + 暗角。冷白底（球场泛光灯）、危险时
  偏暖、进球时压主场色，再加镜头暗角。真实玻璃四角会失光，缺了这一层
  画面就像「有人画出来的」而不是「有镜头对着它」
- 调色画在相机变换内的最后一笔，盖住庆祝演出和射门结果；姓名标签在
  `restore()` 之后绘制，保持不调色 —— 它是叠加层，不属于画面
- 危险度也带出零星闪光（`danger * 0.2`），不只是进球才有

### 实机微调（`8f0201e`）

实机跑焦点直播（红太阳 vs 大同队）发现两处：

- 号码 `height*0.2` 字号 + 纯白 + 重黑描边，在禁区机位下每个球员胸口都
  是一个亮白方块，比球还抢眼。降到 0.17、白色 0.72、描边 0.42，门槛
  13px → 15px
- 客队绿衣在草皮上几乎糊掉。真实足球里撞色靠球衣本身解决，屏幕上只能
  靠轮廓：客队描边 0.74 不透明度，线宽 0.016 → 0.023

## 已知缺口

- **日夜灯光没做**。`MatchdaySnapshot` 里没有开赛时间，`MatchFixture` 也
  只有赛事类型和轮次标签，推不出时段。第 4 层改用气氛驱动的色温 —— 转播
  画面的色温本来就跟着气氛和灯光师走，不跟时钟走。要真正的日夜得给
  fixture 加开赛时间字段，那是引擎和存档的改动
- **tifo 位置由种子决定，可能落在画面外**。真实球场的 tifo 也只在一侧，
  镜头摇过去才看得到，所以这是特性不是 bug，但没有保证每场都能看见
- **竖屏取景方向仍偏怪**：「近端边线在屏幕右侧、远端在左侧」的方向读起来
  不顺，可能需要专门的竖屏机位族
- **预缓存条目 89 / 89 已满**，下一个新增 chunk 会到 90
- 文档第 7 节的另外几条仍然有效：不加慢动作回放、不重写
  `physics.ts` / `sequence.ts`、不新增播放模式、不改 `playbackMotionRate`
  步长、不改比赛模拟引擎
