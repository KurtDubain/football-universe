# 移动端与 PWA 专项审计

审计日期：2026-08-10
实现版本：v4.43.0

## 1. 当前架构

- `src/main.tsx` 挂载根 Error Boundary、BrowserRouter 和全局反馈桥；`index.html` 在应用模块和本地存档恢复完成前提供可访问的静态启动状态。
- `src/app/App.tsx` 只同步加载 Welcome 和应用壳；20 个业务页面通过统一的 `RecoverableRoute` 按需加载。
- Zustand 使用当前格式单存档。读取路径为 `localStorage -> LZ 解压 -> JSON.parse -> 深层结构校验 -> persist merge`；写入路径经 250ms 合并后在 Worker 内序列化和压缩，`pagehide`、隐藏与关闭前同步兜底。
- PWA 使用 `generateSW`、`skipWaiting`、`clientsClaim` 和过期缓存清理。应用壳、Dashboard 及公共依赖进入 precache；带内容哈希的次级页面分包使用 64 项/30 天的 CacheFirst 运行时缓存。
- `version.json`、`index.html` 和 Service Worker 不缓存。启动、回到前台、聚焦、联网及每 15 分钟检查一次部署标识。
- 移动端壳使用 `100dvh`、顶部/底部 safe-area、固定 48px 顶栏、可锁滚动和恢复焦点的导航抽屉；比赛 Canvas 根据 DPR、可见性和 reduced-motion 降级。

## 2. 本轮问题与处理

| 级别 | 问题与根因 | 处理 |
| --- | --- | --- |
| P1 | 裸 `React.lazy + Suspense` 对永久 pending、断网和部署后旧分包缺失没有退出路径 | 每次尝试 8 秒超时；动态分包失败只自动重试一次；最终进入带错误码、反馈信息和三种恢复操作的错误态 |
| P1 | Chromium 会缓存失败的模块 URL，再调用同一 importer 不会产生第二个请求 | 仅从同源 `.js` 错误 URL 构造一次 `__route_retry` 请求；拒绝跨域地址，离线和未知错误不重试 |
| P1 | PWA 接管时只避让推进与弹窗，可能打断路由加载；加载结束也没有安全状态通知 | 更新安全快照加入路由 Loading；路由 ready/error 后发送 settled 事件，待处理更新只刷新一次 |
| P1 | Welcome 的同步初始化异常会让按钮永久停在“正在构建宇宙” | 开始操作先让 Loading 绘制，捕获异常后恢复按钮并明确说明设置和存档未清除 |
| P1 | 存档 hydration 对同一文本执行两次 `JSON.parse` | 读取、解析和校验合并为一次操作，并记录四阶段耗时；损坏存档继续隔离且不静默覆盖 |
| P1 | 旧构建与新部署之间缺少真正的双目录 Service Worker 验证 | 新增旧资源服务切换脚本，验证弹窗避让、一次刷新、入口不混用、存档恢复、新路由和离线重访 |
| P2 | 移动顶栏用 `3rem`，大字号环境下不能保证稳定的 48px 基准；部分全页状态只有 `100vh` | 顶栏改为固定 48px 加安全区，根、Welcome 和全页 Loading 同时提供 `100vh` 回退与 `100dvh` |
| P2 | 平板三列赛季总结会正常截断长姓名，但没有完整可访问信息 | 保留紧凑布局，为球员及球队/位置补充完整 title |
| P2 | 大存档恢复前可能短暂空白 | 在 HTML 壳提供不依赖 React 的恢复状态；当前 150 赛季总恢复 218ms，暂不引入高风险异步 hydration |

本轮没有发现 P0 数据丢失、不可启动、自动刷新循环或生产审计桥泄露。

## 3. Loading 与恢复约束

- 单次页面尝试上限 8 秒；自动重试最多 1 次，总请求最多 2 次。
- `offline / timeout / chunk / network / unknown` 分开记录到当前 session，并触发部署检查。
- 未缓存次级页在离线首次打开时明确提示；已经在线使用过的分包由运行时缓存提供离线重访。
- 页面资源失败不会调用 reset、removeItem 或存档迁移；运行期组件渲染错误仍上抛到根 Error Boundary。

## 4. PWA 策略结论

- 保留内容哈希 JS 的 CacheFirst。它们是不可变资源，NetworkFirst 会增加每次路由切换延迟，并不能解决旧 HTML 指向已删除分包的问题。
- 不把全部次级路由塞进 precache。当前安装包已经包含核心观察链路，次级页采用按需缓存和明确离线错误，在安装体积与首次离线覆盖之间保持边界。
- 新部署由无缓存 `version.json` 发现，再要求 registration update。实际刷新必须满足页面可见、未推进、无阻塞弹窗、无路由 Loading。
- 当前和下一构建依靠不同内容哈希，不共享入口；旧缓存由 Workbox 清理和 64 项上限约束，不会无限增长。

## 5. 自动化证据

- 全路由矩阵：126 个路由/视口组合，覆盖 320x568、360x800、390x844、430x932、768x1024、1280x720、1440x900；0 横向溢出、0 不可达裁切、0 小触控主操作、0 runtime error。
- 交互矩阵：抽屉焦点/锁滚动/Escape/导航、详情返回、键盘整行操作、大字号、reduced-motion、standalone、横竖屏恢复、Welcome、Error Boundary 和离线重访全部通过。
- 页面资源：真实首请求失败后第二请求成功；持续失败严格停在 2 次；离线错误可联网原地恢复；慢速 3G 页面在超时前完成。
- PWA 迁移：旧入口与新入口不同；弹窗期间不刷新，关闭后文档只重载 1 次；存档前后存在；新文档不加载旧入口；History 可离线重访；0 runtime error。
- 当前链路：10 赛季 500 次推进，数据错误、警告和 runtime error 均为 0；存档往返、深链刷新、返回及离线重访通过。
- 长期存档：150 赛季 7,609 次推进，S150 存储 2,046,580 B；恢复 218.1ms，其中解压 167.2ms、解析 30.7ms、校验 20.2ms；S1/S50/S100/S150 重载和下一步摘要全部一致。
- 移动推进：正常 CPU p50/p95 为 18.5/19.3ms，4x CPU 为 43.3/64.6ms；20 次快速触发只接受 1 次且刷新后位置一致。
- Canvas：正常/4x CPU 平均绘制约 0.29/1.14ms；隐藏、遮挡、关闭、连续重开、下一场重置与最终比分全部通过。

## 6. 保留风险与真机门禁

- S150 解压仍在主线程执行，约 167ms；按 4x CPU 粗略估算可能接近 0.7 秒。当前已提供启动状态且总恢复远低于 1 秒，异步 hydration 会扩大闪烁、导出和恢复语义的改动面，暂列 P2 观察项。
- iOS Safari 的地址栏、刘海和 Home Indicator，以及 Android 厂商手势栏只能由 Chromium safe-area/旋转矩阵近似；投稿前仍需至少一台真实 iPhone 和一台 Android 安装 PWA 后检查。
- 未曾在线打开的次级页面不会在离线时凭空可用，这是有意的安装体积策略；错误界面会保留当前存档并等待联网。
- 4x CPU 动画启动阶段观察到长任务，但持续 Canvas 绘制成本很低且交互状态全部正确。低端真机直播开场仍应作为盲测观察点。

结论：工程层面建议进入腾讯游戏大赛候选版本；剩余门禁是实体 iOS/Android PWA、Vercel 线上旧新部署切换和真人 15 分钟路线，而不是继续扩展系统。
